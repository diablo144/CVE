ReconRelay is a small reconnaissance prototype I built to connect information visible in a browser to a server-side discovery workflow. Its extension collects selected page details, including links, script paths, forms, and response headers, then sends them to a FastAPI service. A Python worker filters submitted seeds using the server’s configured target list, follows accepted events within configured limits, and stores job and event data in Redis. The extension shows updates in a popup and a simple graph panel. I kept active TCP checks disabled by default and made the server require a separate setting before they can run. The current tests pass, but they use simulated network responses; they do not prove that the tool finds assets accurately or is ready for public deployment. This paper explains why I built the prototype, how its main parts work, what I tested, and what still needs to be done.
